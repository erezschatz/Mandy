2. what to do, and what passes

  1. Type a few characters mid-word. Each one is a single insertText, the text appears, and divergence stays quiet.
  2. Select a word and type over it. One insertText whose target range is the selection.
  3. Backspace mid-word, then Delete (fn+Delete on a Mac). deleteContentBackward / deleteContentForward, each with a target range one character wide.
  4. Delete a word — Option+Backspace on a Mac, Ctrl+Backspace elsewhere. One deleteWordBackward whose range covers the whole word: the engine decides what a word is, and we do not. Do this on the last word of a bullet too, which is where the space before it has to survive — the model keeps it, the screen keeps it, and the file does not, because markdown strips it on the next parse.
  5. Backspace at the very start of a paragraph. The range spans two blocks — the log says so — and the two join, with the caret landing exactly where they meet. Slice 4 turned this from a refusal into the handling, and it fell out of getTargetRanges() rather than being worked out from the keystroke.
  6. Type an accented character — hold e on a Mac, or use a dead key. compositionstart, then the engine writes while we wait, then compositionend applies it as one edit.
  7. Type into the bold run, at its very end, and at its very start. The end continues bold; the start does not.
  8. Click on the equation itself and type a letter. The letter appears beside it and the equation survives — the range in the log is collapsed, n–n. This is the one Gecko found on 2026-09-20: a caret inside the span used to report 12–13 and the letter ate the equation.
  9. Drag across the equation — all of it or any part of it — then type. Now it is replaced, and the range in the log spans it, n–n+1, however little of it you dragged over. That is the atom rule, not a slip: an equation is one character in the model's offset space, so a selection either covers it or it does not and there is no half of it to keep. The pair with the step above is the point — one position is not a range.
  10. Click just after the image and type. The letter lands after it; the image survives. Then select the image — drag across it, or click it and use Shift+Arrow — and type: it is replaced, whole, for the same reason. It is one character, the same as the equation.
  11. Press Ctrl/Cmd+Z. Cancelled, and nothing moves: undo is slice 6.
  12. Press Enter mid-paragraph. It splits into two, the caret is at the start of the second, and the divergence line stays quiet. Then Enter at the end of the heading: what opens is a paragraph, not a second heading.
  13. Press Enter in the middle of a list item. You get a second bullet, not two paragraphs inside one — Enter splits the block and then the item above it. Then Enter at the end of the last bullet to get an empty one, and Enter again: the empty item leaves the list for a paragraph.
  14. Press Tab and Shift+Tab inside a bullet. The item nests under the one above it and comes back out, with its followers along. This is the move tests/list-indent-check.html watches three engines make on the old core; here there is no engine in it.
  15. Press Shift+Enter mid-line. A hard break: the line wraps and the caret is on the second half.
  16. Click inside the fenced code block and type. Its body is edited as source — the second text space — and Enter inside it is a newline in the body rather than a new block.
  17. Try to click inside the table, then type. Nothing changes either way — a table is rendered contenteditable="false" until stage 3, so an edit inside one is refused. Whether the caret goes in at all is per engine, and Blink is the odd one out, measured in all three on 2026-09-21: Blink keeps it out, so the door is visibly closed; Gecko and WebKit both let the caret in, and typing then does nothing — the reading the refusal was meant to avoid, in two engines out of three. Report which you get. Selecting across the table still works everywhere.
  18. The table is the last thing in the document — click below it and type. There is somewhere to go, because an empty paragraph is kept after it. This is the contenteditable="false" caret trap, and it is the one thing in slice 4 that could make a document un-appendable.
  19. Paste some plain text mid-sentence — copy a line from anywhere and press Ctrl/Cmd+V. It lands at the caret, the sentence stays one sentence, and the log shows a cancelled paste rather than an insertFromPaste. Then paste something markdown-shaped, like *not emphasis*: it stays literal, because plain text is never parsed.
  20. Paste several paragraphs at once, into the middle of one. The paragraph splits, the first pasted block joins the head, the last joins the tail, and whole blocks land between. The caret ends where the tail rejoins.
  21. Copy something formatted from a web page and paste it. On this page the HTML branch cannot run — it needs app.js's Turndown, which this page deliberately does not load — so it falls through to the plain text. What is being measured here is the engine: check the log says the paste was cancelled, and that nothing diverges. The HTML pipeline itself is the model suite's. To see it end to end, open the app at /?core=model — the flag that makes the editor draw from the model — and paste the same thing there: the bold, the links and the lists should survive. Switch back with /?core=legacy, and note that under the flag the formats and Ctrl+Z do nothing, because they are slices 6 and 7.
  22. Select a few words and drag them somewhere else in the document. They move: the original goes and the text lands where you dropped it. This is the one that fails silently if it fails — the engine raises deleteByDrag and insertFromDrop as a pair, both are cancelled, and doing only the insert would duplicate the text and look like it worked.
  23. Drag the same selection onto itself, then drag one spanning two blocks. Both do nothing at all, on purpose. Report if either moves anything.
  24. Drag some text in from another window and drop it. It lands where the pointer was, not where the caret was — which needs caretPositionFromPoint or caretRangeFromPoint, and which of those answers is per engine. Report if the drop lands in the wrong place.
  25. Use the toolbar's formats — there is no toolbar here, so skip this one. In the app with ?core=model, the format bar does nothing on purpose: execCommand fires input but never beforeinput, measured in Chrome 152, so it cannot be intercepted and is refused rather than allowed to change the DOM behind the model's back. Formats arrive as model commands in slice 7.

Fail is any of: a character that does not appear, a caret that jumps, the divergence line at the top lighting up, or an inputType reported as not cancelable. The divergence line is sticky and counts, and every divergence is written into the log as well, so one that comes and goes is still there to be found.
