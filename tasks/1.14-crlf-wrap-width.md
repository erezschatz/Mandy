# 1.14 — A CRLF file's wrap width is sniffed a column wide

## Context

Found on 2026-11-19 by task 1.13, which made a CRLF file editable and so made
this reachable; its reader asked for a task to hold it. `sniffMarkdownStyle` in
`front/markdown-style.js`, called by `adoptMarkdownStyle` in `app.js` on the raw
file, splits on `\n`, so every line of a CRLF file it measures still ends in
`\r` and is one character longer than it reads. Measured that day: the wrap
width of a CRLF copy of `tests/fixtures/break-test.md` is 79 where the LF
original's is 78, and `torture.md` and `corpus/todo.md` move the same way;
nothing else the sniff reports differs. So an edited paragraph in a CRLF file
is re-wrapped one column wider than its neighbours.

Not started. The likely fix is to sniff the same LF text `modelParse` holds
(task 1.13, D33), with a `save-fidelity` check that a CRLF file and its LF twin
sniff alike; which side of the call the normalisation goes on is this task's
to decide.

**A second effect, found while planning**: both hard-break patterns end in `$`
(`/ {2,}$/` and `/[^\\]\\$/`), and in a CRLF file the `\r` sits before the end,
so neither ever matches. A CRLF file written with backslash breaks is sniffed
as two-space, and a break typed into it is spelled the other way.

### The plan

Started 2026-11-19, asked for by the user.

1. `sniffMarkdownStyle` turns every `\r\n` and lone `\r` into `\n` before it
   reads anything, so the sniff sees the text the model holds.
2. `save-fidelity` checks: a CRLF copy and a lone-`\r` copy of
   `tests/fixtures/break-test.md` and `tests/fixtures/torture.md` sniff exactly
   as the LF original does, every field; `tests/fixtures/crlf.md` sniffs as its
   LF twin; and a CRLF file written with backslash breaks sniffs as backslash.
3. Records: CHANGELOG.md, this file.

## Decisions

### 2026-11-19 · The sniff normalises line endings itself

**Decision** — `sniffMarkdownStyle` turns `\r\n` and a lone `\r` into `\n`
before it reads, so whatever hands it a file gets the same answer for any
line ending.
**Rejected** — Normalising in `adoptMarkdownStyle` in `app.js`, the one caller
that hands it a file: it would fix today's caller and leave the function
wrong for the next one. Having `modelParse` hand its LF text to the sniff:
it ties the style module to the model's door for one `replace`.
**Why** — The sniff's answer is a fact about the file's conventions, and a
line ending is not one of them (D33); a pure function that is right for every
input is the cheapest place to keep that true.

## What was done

2026-11-19: **done and tested by machine.** `sniffMarkdownStyle` normalises
line endings at its top, once, for every read in it — the table convention read
the raw argument a second time, found by the lone-`\r` check, which is why the
plan's one `replace` became a reassignment. The six `save-fidelity` checks of
the plan landed as written, and all six fail against the old sniff. `front/sw.js`
goes to `v1.99`; `npm test` passes. **What no suite reaches**, for the user:
open a CRLF file with backslash hard breaks in Mandy, press Shift+Enter in a
paragraph, save, and the new break should be a backslash; and in a hard-wrapped
CRLF file, a paragraph lengthened by typing should wrap at the same column as
its neighbours. CHANGELOG.md has the rest.
