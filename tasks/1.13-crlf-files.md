# 1.13 — Editing a CRLF file mixes its line endings, and can throw

## Context

Found on 2026-11-19 by task 1.12's stage 1, while it made its own gap bytes
CRLF-aware, and recorded there as out of scope; handed to its own session the
same day. Measured with the `model` suite's loader and a configured
markdown-it:

- `modelParse("# Title\r\n\r\nA.\r\n")`, then `modelInsertParagraph` at offset 0
  of `A.`, serialises with `A.\n` at the end — a bare line ending in a CRLF
  file — and before task 1.12 the separator in front of it was `\r\n\n`.
- Enter at the end of the last paragraph of `"A.\r\n"` (offset 2), or of
  `"A.\r\n\r\nB.\r\n"`, throws `edited paragraph block whose first line does
  not start with its own affix` in `modelEmitLeaf`, so the save refuses the
  document.

**Why.** The model keeps a block's bytes exactly as the file had them, so a
CRLF file's `source`, `separator` and prefix all carry `\r\n`. markdown-it
normalises every line ending to `\n` before it parses, so `inline.content`,
which the affix checks in `modelEmitLeaf` compare a block's first line
against, has none — `A.\r` does not end with `A.`. And every place the model
composes bytes (about eighty literals in `front/model.js`: separators, split
halves, merged lines, wrapped lines, table rows, fences) writes `\n`, so any
edit in a CRLF file writes LF lines into it. Every Playwright spec and every
oracle file is LF, which is why none of this has shown before.

### The plan

**Line endings are decided at the door, once per document.** `modelParse`
counts the file's line endings, records the commonest as `doc.eol` (`"\n"`,
`"\r\n"` or `"\r"`, LF on a tie or on a file with none), and parses the text
with every `\r\n` and lone `\r` turned into `\n` — which is what markdown-it
does anyway, so the model's bytes and the parser's agree for the first time.
`modelSerialise` turns `\n` back into `doc.eol` on the way out, so it is the
one place a file's line ending is written. Inside the model every byte is LF.

What that changes, in order:

1. **`modelParse` and `modelSerialise`**, as above. `modelForkDocument` already
   copies the document's own fields, so an undo state and a parked tab carry
   `eol` with no change; a document made from `parse("")` is LF.
2. **`modelJoinBlocks`' CRLF branch goes.** Task 1.12 taught it to write a
   gap in the line ending of the separator before it; with an LF model that
   is the conversion's job, and D7 says a fix that makes a workaround
   unnecessary takes the workaround with it.
3. **Pastes need nothing**: a pasted markdown fragment goes through
   `modelParse` and arrives LF, a plain-text paste is already normalised by
   `modelTextBlocks`, and both are written in the target document's line
   ending by the conversion.
4. **The `model` suite** gains CRLF cases, each asserting the file holds no
   bare `\n` and no lone `\r` afterwards: Enter mid-file, Enter at the end of
   the last paragraph (the throw), Backspace merging two paragraphs, an inline
   edit, and a paste of several blocks; plus a fixture,
   `tests/fixtures/crlf.md`, held with CRLF endings, that round-trips byte for
   byte and survives every inline-bearing block edited alone with only CRLF
   written — the oracle's own sweep, in a CRLF file. A mixed file and a lone
   `\r` file get one check each for the decision below.
5. **Records**: this file, CHANGELOG.md, the `model` entry in CLAUDE.md only
   if it names a figure (it must not), and task 1.12's note that this was
   out of scope stays as written.

**Not in this task**: `sniffMarkdownStyle` in `markdown-style.js` reads the
raw file and splits on `\n`, so on a CRLF file every line it looks at ends in
`\r`. Whether that skews the sniff (a two-space hard break, the wrap width) is
unmeasured; if it does, that is its own fix.

*Measured the same day, while this landed*: it does. On `break-test.md`,
`torture.md` and `corpus/todo.md` the wrap width of a CRLF copy reads one
column wider than the LF original's (LF 78, CRLF 79 on the first), because
the `\r` is counted in each line's length; nothing else the sniff reports
moved. So an edited paragraph in a CRLF file is re-wrapped a column wide. Not
fixed here: it is [1.14](1.14-crlf-wrap-width.md).

## Decisions

### 2026-11-19 · A file's line ending is the document's, sniffed once

**Decision** — `modelParse` records the commonest line ending in the file as
the document's and holds the text as LF; `modelSerialise` writes every line
ending as the document's. A uniformly CRLF file comes back byte for byte and
an edit in it writes only CRLF. A file whose line endings are mixed is written
wholly in its commonest one on its first save, edited or not.
**Rejected** — Keeping each block's bytes as the file had them and teaching
every place that composes bytes to use the document's ending, and every affix
check to ignore a trailing `\r`: about eighty sites, each a place to forget,
and the model's bytes and the parser's would still disagree. Recording each
line's own ending so a mixed file keeps its mix: a line's ending would have to
follow it through every split, merge and paste, for a file that is almost
always an accident.
**Why** — A line ending is whitespace nobody can see, the category D3 already
narrows D1 for; a mixed file is the damage D3 describes, not a spelling an
author chose. A uniform file is the case worth keeping exactly, because
rewriting every line of it would be the whole-file diff D1 exists to prevent,
and that is what this keeps.

## What was done

2026-11-19: **done and tested by machine.** `modelParse` records the file's
commonest line ending as `doc.eol` (`modelSniffEol`) and parses the text as LF;
`modelSerialise` writes every line ending as `doc.eol`; `modelJoinBlocks`'
CRLF branch from task 1.12 is removed. The plan's steps 1 to 4 landed as
written, and step 5 needed no CLAUDE.md change. One thing the plan did not
know: **a file with lone `\r` endings did not parse at all** before this —
`modelParse` threw on it — and now opens, edits and saves in `\r`.

The `model` suite has eleven CRLF edit cases (Enter, Backspace's merge, an
inline edit, a hard break, a fence edited as source, and three pastes), seven
on the sniff and the model's LF, and the `tests/fixtures/crlf.md` round trip
and sweep against its LF twin. Against the old code every one fails but
three, which held already: the CRLF fragment pasted into an LF file, the
fixture's round trip (D1 held for an untouched CRLF file before) and the guard
that the fixture is CRLF at all. The sweep fails 35 of its 36 edits there, and
the lone-`\r` check throws out of `modelParse` and stops the suite. Task
1.12's CRLF check asserts the whole file now. `.gitattributes` marks the
fixture `-text`. `front/sw.js` goes to `v1.98`. `npm test` passes; Playwright
was not run, since no spec opens a CRLF file. **What no suite reaches**, for
the user: write a file with CRLF endings outside Mandy (`printf 'A.\r\n\r\nB.\r\n' > /tmp/crlf.md`),
open it in Mandy, press Enter at the end of `B.`, type a word, save, and run
`file /tmp/crlf.md` — it should say *with CRLF line terminators* and nothing
about mixed ones. CHANGELOG.md has the rest.
